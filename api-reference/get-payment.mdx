---
title: "Get a payment"
api: "GET {BASE_URL}/api/v1/payments/{id}"
description: "Returns the current status and, once final, the result to reconcile against."
---

## Path parameters

<ParamField path="id" type="string" required>
  The payment id (UUID) returned when you registered the payment.
</ParamField>

<RequestExample>
```bash cURL
curl "{BASE_URL}/api/v1/payments/6c1d9a3e-2f0b-4a7e-9d51-0b3a7c2e9f14" \
  -H "x-api-key: $MIZANIYA_API_KEY"
```
</RequestExample>

## Failed payment

Only `data` differs: `status` is `failed` and `error` is filled in.

```json
"status": "failed",
"error": {
  "code": "CARD400_INSUFFICIENT_FUNDS",
  "message": "The card has insufficient funds"
}
```

See all [payment failure codes](/errors/payment-failure-codes).

## Errors

| HTTP | errorCode | Cause |
|---|---|---|
| 400 | `VALIDATION400_BAD_REQUEST` | `id` is not a UUID. |
| 404 | `PAYMENT_INSTANCE404_NOT_FOUND` | No payment with this id for your key. |

<Tip>
Use this endpoint to confirm a result or to recover if a webhook was missed. Check [payment statuses](/concepts/payment-statuses) to know what to do for each.
</Tip>
